현재 브랜치를 기준으로 GitHub Pull Request를 생성합니다.
PR은 반드시 연결된 이슈가 있어야 합니다.

## 진행 순서

1. **현재 상태 파악**
   - `git status`, `git log dev..HEAD --oneline` 로 변경사항 확인
   - 브랜치명에서 이슈 번호 추출 (예: `feat/#12-add-ticket` → `#12`)

2. **이슈 번호 확인**
   - 브랜치명에서 이슈 번호를 찾을 수 없으면 사용자에게 물어보세요
   - 이슈가 없다면 작업을 멈추고 안내하세요:
     > PR은 반드시 이슈와 연결되어야 합니다. 먼저 `/new-issue` 로 이슈를 생성해 주세요.

3. **PR 제목 작성**
   형식: `<type>: <작업 요약> (closes #<이슈번호>)`
   예) `feat: AlertBanner 컴포넌트 추가 (closes #12)`

4. **PR 본문 작성** (아래 템플릿 사용):

```
## 관련 이슈
closes #<이슈번호>

## 변경 사항
- 변경 내용 1
- 변경 내용 2

## 작업 내용 상세
(구현 방식, 주요 결정 사항 등)

## 체크리스트
- [ ] `npm run build` 성공 확인
- [ ] `npm run lint` 에러 없음
- [ ] 에러/로딩 상태 처리 포함
- [ ] 다크 모드 스타일 적용 (gray-900/800/700 팔레트)
- [ ] API 호출은 app/lib/api.ts 에서만 관리
- [ ] 민감 정보 (API 키 등) 코드에 포함되지 않음
```

5. `gh pr create` 로 PR을 생성하세요:
   - base 브랜치: `dev`
   - 생성 후 PR URL을 사용자에게 알려주세요
   - **PR은 직접 머지하지 않는다. 생성 후 대기.**

6. PR 생성 후 안내:
   > 팀원에게 리뷰를 요청하거나, `/review-pr <PR번호>` 로 AI 코드리뷰를 먼저 받아보세요.
